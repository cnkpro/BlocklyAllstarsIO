# Roadmap

Work items for reviving Blockly.IO, roughly in priority order. Mark an item `[x]`
when it is done and add a one-line note (date, commit) under "Log".

## Backlog
- [x] End-of-game score screen: fill the empty `#stats` panel (land %, kills, time alive, rank) before returning to the login screen (upstream issue #1)
- [x] Centralize magic numbers (CELL_WIDTH, SPEED, ANIMATE_FRAMES, NEW_PLAYER_LAG, ...) in `game-core/game-consts.js` (upstream issue #2)
  - Left as-is: client-only layout constants in `user-mode.js` (bar sizes, bounce/drop animation) and the 60 fps / timeout values in `client.js`; move them too if the server ever needs them
- [x] Replace the "Todo: replace ^^^ with a picture" title placeholder with a proper logo/title
  - Done as a CSS tile logo (no image). Needs a look in a real browser; swap in an image later if wanted
- [x] Mobile support: swipe / on-screen controls and a responsive canvas (upstream issue #14)
  - Done: swipe controls (`client-modes/swipe.js`), on-screen arrow pad (`#dpad`, touch screens only), UI bar and leaderboard sized by screen width (`client-modes/hud-layout.js`), start/score screens fit on phones
  - Not checked in a browser or on a real touch device yet (preview server declined in the automated runs). Worth a look: D-pad position over the leaderboard on short landscape screens
- [x] Re-enable client/server frame verification in `client.js` (currently commented out) and resync on mismatch
- [x] Keep kill count and zoom when the client re-requests a frame (TODO in `client-modes/user-mode.js`)
  - No automated test for the resync path yet (the client socket is private); worth a manual check by forcing a `requestFrame`
- [x] Death animation: tail rewinds / player explodes (TODO in `user-mode.js`)
  - Done as: block bursts into 3x3 pieces and the tail fades out over `ANIMATE_FRAMES`. A real tail "rewind" is still open if wanted; not checked in a browser yet
- [x] Server: support more than one game room instead of `games[0]` only
  - Empty rooms other than the first are closed after each tick (`Game.closeEmpty`); ids of closed rooms are reused. Still open: show the room number in the client (`TODO` in `client.js`)
- [x] Add unit tests for tail filling (`fillTail` / `floodFill`) and Color
- [x] Add an ESLint config and fix warnings (implicit globals like `steps`, `distWeights` in bot-mode.js)
  - `npm run lint`: 0 errors, 9 warnings left (unused debug helpers in the bots, `gridWidth` in `user-mode.js` used by commented-out code); decide whether to delete them
- [x] `npm audit` reports 2 critical issues in `sha.js` / `crypto-browserify` pulled in by browserify (build-time only); check whether upgrading or replacing browserify is worth it
  - Fixed with `npm audit fix` (crypto-browserify 3.3.0 -> 3.12.1, lockfile only). 4 low-severity reports remain for `elliptic` (no fixed release; build-time only)
- [x] Server runs at ~36 instead of 60 frames a second on Windows (`setTimeout(tick, 1000 / 60)` fires late), so the whole game is ~40% slow there (found in code review)
  - Fixed with a catch-up ticker (`ticker.js`); when the timer wakes late, two frames can go out at once, so check that movement still looks smooth in a browser
- [x] New players can spawn on another player's tail or next to their head (`findEmpty` only checked owned land), which kills that player on the spot (found in code review)
  - Fixed: spawn spots also avoid every tail cell and the 5x5 area around each head
- [x] Client hangs (endless loop) when it resyncs after a missed frame: the cached-frame replay in `client.js` started one frame too early, which mismatched and re-requested forever (found in code review)
  - Fixed: replay skips cached frames the new game state already includes; tested with a fake socket. Not reproducible by hand in a browser (needs a dropped frame)
- [x] Clients give a player's start area to a throwaway copy when that player is announced as new but already in the loaded game state (joined in the same frame, or right before a resync), so the client draws a tail the server doesn't have (found in code review)
  - Fixed: `processFrame` skips new players it already knows; tested with the fake socket
- [x] W, A, S, D and the arrow keys can't be typed into the name field: the steering key handler swallowed them everywhere (found in code review)
  - Fixed: key mapping moved to `client-modes/keys.js` (unit-tested) and ignores keys typed into text fields; not checked in a browser (preview server declined)
- [x] A refused join ("All games are full!") left the client's socket open; bots retry every second, so a full server collected one more open socket per bot per second (found in code review)
  - Fixed: `connectGame` closes the socket when `hello` fails (tested with the fake socket)
- [x] Keyboard steering can stop working right after pressing Enter to play: the name field is hidden but may keep the focus, and the steering handler ignores keys typed into text fields (regression from the W/A/S/D fix, found in code review)
  - Fixed: the login screen's focused element is blurred on join, and `keys.js` only treats a text field as typing while it is shown (unit-tested); not checked in a browser (preview server declined)
- [x] Clicking Play while the login screen is still fading in after a game wiped the new game's score: `stats.reset()` ran when that fade finished, so the next score screen showed 0% land, 0 kills and 0:00 (found in code review)
  - Fixed: stats are cleared when a new game loads (renderer `reset`, not on a resync); DOM code, so no unit test, and not checked in a browser
- [x] Play silently did nothing after the server was unreachable or dropped before the game loaded: `connectGame` only reset its `running` flag on a refused join or after a game, so a page reload was needed (found in code review)
  - Fixed: connection errors and early disconnects end the attempt with an error message (or go back to the login screen if the join was already accepted); bots now retry instead of waiting on a dead socket. Tested with the fake socket
- [x] A player whose whole territory was enclosed by someone else stayed alive with no land: they could never fill their tail again and just wandered until they hit a wall or got cut (found in code review)
  - Fixed in `updateFrame` (game-core, so server and clients agree): players without any land are out, like in paper.io. The enclosing player gets no kill for it; decide whether it should count as a kill
- [x] Death animations were cut off when the client resynced: `reset` cleared them even when keeping the view (found in code review)
  - Fixed: a resync keeps running death animations. DOM-side, no unit test; not checked in a browser (needs a resync during a death)
- [x] `npm test` could hang forever: the server tests waited a fixed 1s for the server to start, and on a slow (cold) start the socket's `hello` ack never came back; the spawned server then kept the test process alive (found when the 23:00 run's first `npm test` never finished)
  - Fixed: the test waits for the server's "listening" line (fails after 15s), a 120s watchdog fails the run instead of hanging, and spawned server/bot processes are killed when the test exits
- [x] Score screen is only fully visible for an instant: it fades in over 3s and then the login screen immediately fades in on top of it, so both overlap (found in a browser play-test). Hold the score screen (e.g. ~4s, or until a click/key) before fading in the login screen, without the overlap
  - Fixed: score screen fades in (1s), stays for 4s or until a click, key or tap (`client-modes/hold.js`, unit-tested), fades out, then the login screen fades in. Not checked in a browser (preview server declined)
- [ ] Death animation is cut short: in a browser the 3x3 burst shows at the moment of death, but the pieces and the tail are gone within 250 ms instead of fading out over the animation (found in a browser play-test)
- [ ] Login screen: the blue GitHub link is hard to read on black; the player name on the score screen is very small (found in a browser play-test)
- [ ] Phone layout: the arrow pad covers the bottom-right of the play area, so you can't see what's coming when heading down/right; consider making it smaller or semi-transparent (found in a browser play-test)
